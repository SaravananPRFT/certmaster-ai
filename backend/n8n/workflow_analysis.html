Now uses a fixed EXPECTED_EXAMS list to catch exams that are missing from chroma_db_stats entirely (not just those with 0 chunks). Returns a single item with has_gaps flag and arrays — so the IF node only needs one check.

// Output: { needs_index: [...], healthy: [...], has_gaps: bool, checked_at }

Node: Any Gaps? New

Type: n8n-nodes-base.if

Checks $json.has_gaps === true. TRUE → auto-fix loop. FALSE → All Healthy terminal node. Prevents any indexing work when everything is already healthy.

Node: Filter Failing Exams New

Type: n8n-nodes-base.code

Extracts the needs_index array from Identify Gaps output and emits one item per failing exam. These feed into the loop below.

return data.needs_index.map(exam => ({ json: exam }));
// e.g. outputs: { exam_code:"AZ-104", issue:"EMPTY", current_chunks:0 }

Node: Process Gaps One at a Time New

Type: n8n-nodes-base.splitInBatches · batchSize: 1

Loop controller. Processes each failing exam one at a time to avoid overloading the backend. Log Re-index Result feeds back into this node to advance to the next exam.

Node: Trigger Re-index Per Exam New

Type: n8n-nodes-base.httpRequest · POST · retry: 2×

Calls POST /admin/index-documents for the specific failing exam. Uses ={{ JSON.stringify({ exam_code: $json.exam_code, ... }) }} — no hardcoded "all".

Node: Log Re-index Result New

Type: n8n-nodes-base.code

Checks the API response and logs success or an actionable failure message. Loops back to Process Gaps One at a Time.

if (r.status === 'success')
  console.log('[WF1 Auto-fix] AI-102: SUCCESS — 847 chunks')
else
  console.error('[WF1 Auto-fix] AI-102: FAILED — check backend logs')

Node: All Healthy New

Type: n8n-nodes-base.code · Terminal

FALSE branch. Logs "all exams healthy" and ends the workflow. No API calls, no indexing.

WF1 → Auto-Fix Chain Explained

The user asked: "Can WF1 trigger WF2 & WF3?" Yes — and WF1 now does this, but using a direct API call rather than n8n's Execute Workflow node. Here is why and how.
ApproachHow it worksTrade-off
Option A — Direct API (implemented) WF1 calls POST /admin/index-documents directly for each failing exam — same endpoint WF2/WF3 use ✅ No workflow ID dependency. Self-contained. Works immediately after import.
Option B — Execute Workflow (optional) WF1 uses n8n's Execute Workflow node to trigger WF3 by its database ID ⚠️ Requires knowing WF3's ID after import. WF3 now has Execute Workflow Trigger so this is ready to wire up.

To use Option B: import all workflows → get WF3's ID from n8n URL → add Execute Workflow node to WF1's gap-fix branch → set workflow ID → pass { exam_code, scraped_dir, clear_first }.

Still Needs Backend / Environment Work (3 items)

Issue #6 — Authentication on Admin Endpoints

Problem: Anyone on the Docker network can call /api/v1/admin/index-documents with clear_first: true and wipe the entire ChromaDB database.

Backend fix (FastAPI):

# In your FastAPI admin router, add a dependency:
from fastapi import Security, HTTPException
from fastapi.security import APIKeyHeader

api_key_header = APIKeyHeader(name="X-API-Key")

def verify_admin_key(key: str = Security(api_key_header)):
    if key != os.environ["ADMIN_API_KEY"]:
        raise HTTPException(status_code=403, detail="Invalid API key")

@router.post("/admin/index-documents", dependencies=[Depends(verify_admin_key)])
async def index_documents(...): ...

n8n fix (after backend is secured): In every HTTP Request node that calls /admin/*, add a header:

Header NameHeader Value
X-API-Key{{ $env.CERTMASTER_ADMIN_KEY }}

Store the key in n8n's environment variables (Settings → Environment Variables).

Issue #13 — host.docker.internal Won't Work Outside Docker Desktop

Problem: host.docker.internal resolves on Docker Desktop (Mac/Windows) but fails in Kubernetes, Linux server, or cloud deployments.

Fix — Use n8n environment variable:

  1. In n8n: Settings → Environment Variables → Add BACKEND_URL = http://host.docker.internal:8003
  2. In all 5 workflows, replace every hardcoded URL with: ={{ $env.BACKEND_URL }}/api/v1/admin/...
  3. When deploying to production, change only the environment variable — all workflows update automatically
Issue #8 — True Content-Change Detection in WF5

Problem: WF5 captures last-modified headers but never compares them to a previous scan. It can only detect if a URL is up/down, not if content changed.

Future enhancement approach:

  1. Add a FastAPI endpoint: GET/POST /admin/url-snapshots that stores { exam, url, last_modified, etag } per scan
  2. In WF5 after Extract Last-Modified, call GET /admin/url-snapshots?exam=AI-102 to retrieve the previous value
  3. Compare current last_modified to stored value — if different, flag as "content changed"
  4. After processing, call POST /admin/url-snapshots to save the new baseline
