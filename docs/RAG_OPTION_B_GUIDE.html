What is RAG? — Simple Explanation

Retrieval Augmented Generation in plain terms

Think of RAG like an open-book exam for Claude.

Without RAG (Option A — current)

You ask Claude a question → Claude answers entirely from its training memory → May be imprecise, difficult to verify, no source citation

With RAG (Option B)

You ask Claude + hand it the exact Microsoft Learn pages → Claude answers from those pages → Grounded, citable, traceable to source

The "book" Claude reads is your local ChromaDB database. The "pages" are Microsoft Learn articles you have loaded into it. ChromaDB finds the most relevant pages for each question topic and hands them to Claude automatically.

💡
Key insight: ChromaDB is not an AI service. It is a fast searchable filing cabinet that stores text chunks alongside their mathematical vector representations. You load documents into it once; it serves them on demand for every question generation request.

How Option B Works End-to-End

Two distinct phases: one-time setup and per-request runtime

Phase 1 — Setup (done once by you)

┌─────────────────────────────────────────────────────────────────┐ │ STEP 1: You collect Microsoft Learn URLs for each exam │ │ e.g. https://learn.microsoft.com/azure/ai-services/... │ │ ~30-50 URLs per exam, saved in a text file │ │ │ │ STEP 2: Download script visits each URL │ │ → Extracts clean text, strips navigation/HTML │ │ → Saves as .txt files on your machine │ │ │ │ STEP 3: Indexing script reads each text file │ │ → Splits into chunks (~500 words each) │ │ → Converts each chunk to a vector (384 numbers │ │ that represent the meaning of that text) │ │ → Stores chunk + vector in ChromaDB on disk │ │ │ │ RESULT: ChromaDB folder on disk (~200MB for all 6 exams) │ │ Survives restarts, searchable in milliseconds │ └─────────────────────────────────────────────────────────────────┘

Phase 2 — Runtime (every time a question is generated)

User starts exam: AB-100, Practice mode, 20 questions │ ▼ Backend picks objective (weighted random from blueprint) e.g. "Describe Features of NLP Workloads on Azure" │ ▼ Query = "AB-100 NLP Workloads Azure features Medium question" │ ▼ Sentence-transformer converts query → vector (384 numbers) │ ▼ ChromaDB compares query vector against ALL stored chunk vectors → Returns top 5 most similar chunks (cosine similarity) → Each chunk is actual text from a Microsoft Learn page │ ▼ Those 5 chunks injected into Claude prompt: "Using ONLY the following text, write a question..." [SOURCE: NLP Overview | learn.microsoft.com/...] Azure AI Language supports key phrase extraction, sentiment analysis, NER across 80+ languages... │ ▼ Claude generates question grounded in those specific chunks → Correct answer traceable to the source text → Citation URL included in question's references field → Grounding score computed against retrieved chunks

Human Effort Required — Step by Step

What you personally need to do vs. what runs automatically

  • 1

    Collect Microsoft Learn URLs for each exam  ~2–3 hours · one time

    Go to learn.microsoft.com and find the official documentation pages for each exam's domains and objectives. Aim for 30–50 pages per exam (180–300 total). Paste URLs into a plain text file, one per line. Stick to official Microsoft Learn pages — not blog posts or third-party tutorials. This is the most important human judgment task in the entire setup because the quality of your URL list determines the quality of every question generated.

  • 2

    Run the download script  ~15 min · automated

    One command. The script visits each URL, extracts article text, saves clean .txt files. No manual reading. For 300 pages this takes about 15 minutes. The script logs any 404s (deleted pages) so you can replace them.

  • 3

    Run the indexing script  ~5 min · automated

    One command. The script chunks all text files, generates vectors using a local model (downloads once, ~90MB), and loads everything into ChromaDB on disk. Result: a ./chroma_db/ folder your backend reads from.

  • 4

    Spot-check quality  ~30 min · one time

    Run a few test queries and confirm the top results make sense. Example: query "Azure AI Language key phrase extraction" should return the key phrase extraction overview page. If it doesn't, the URL list may be missing that topic.

How Questions Are Grounded

The mechanism that ensures Claude cannot invent facts

Concrete Example

The chunk retrieved from ChromaDB:

[SOURCE: Key Phrase Extraction Overview | learn.microsoft.com/azure/ai-services/language-service/...] Key phrase extraction is a feature of Azure AI Language that identifies the main concepts in text. It does not require training data. It supports 80+ languages and returns key phrases as a list of strings. It is available via REST API and the Azure SDK for Python, .NET, Java, and JavaScript.

What Claude is instructed:

"Using ONLY the text above, generate a Medium difficulty MultipleChoiceSingle question for the AB-100 exam on the objective 'Features of NLP Workloads on Azure'. Set blocked=false, grounding_score=0.92, citation_coverage=0.88."

What Claude produces:

{ "question": "A developer needs to extract the main topics from customer feedback text without building a custom model. Which Azure AI Language capability should they use?", "options": [ {"id": "A", "text": "Custom text classification"}, {"id": "B", "text": "Key phrase extraction"}, ← correct {"id": "C", "text": "Conversational Language Understanding"}, {"id": "D", "text": "Named entity recognition"} ], "correct_answer": ["B"], "explanation": "Key phrase extraction identifies main concepts without training data...", "references": [{"title": "Key Phrase Extraction Overview", "url": "learn.microsoft.com/azure/ai-services/language-service/..."}] }
✅
Why this is reliable: The fact "does not require training data" comes directly from the Microsoft Learn page. The URL in the question's references field points to the exact source. A reviewer can click that link and verify the answer. Claude cannot invent a fact that isn't in the chunk — and the grounding score gate rejects questions where it tries.
⚠
Limitation: Claude can only ask questions about topics that are in your indexed pages. If you did not include the Azure AI Translator documentation, no questions about translation will be generated for AI-102 (or they will fall back to Claude's knowledge). This is why your URL list quality is the critical human input.

Managing the knowledge base over time

Staying Current — Practical Workflow

Microsoft typically revises exam content 2–4 times per year. The signal is the "Skills measured" section on the official exam page (e.g. learn.microsoft.com/certifications/exams/ai-102).

When that page changes, the refresh process is:

  • Update your URL list if new topics are added
  • Run: python scripts/download_docs.py
  • Run: python scripts/index_docs.py
  • ChromaDB is refreshed — new questions reflect updated content

Total time to refresh after a Microsoft exam update: approximately 1 hour.

🔔
Recommended monitoring: Subscribe to the RSS feed or "Watch" the exam skills outline pages on Microsoft Learn. You will receive a notification when the page is updated, which is your cue to refresh the index.

Recommended Phased Roadmap

From POC today to production-grade RAG when Azure is approved

Now

Option A — Knowledge-based generation

Portkey + Claude generating questions from training knowledge. Already working. Use for internal development and initial demos. No further setup needed.

Next Step

Option B — Local ChromaDB + Microsoft Learn docs

~4 hours setup. Introduces real grounding, verifiable citations, and a compelling stakeholder story. Recommended before any formal POC presentation. The retriever interface stays identical — switching to Azure AI Search later requires only changing the backend of retriever.py, with zero frontend or API contract changes.

Production

Azure AI Search + Azure OpenAI (when approved)

Replace ChromaDB with Azure AI Search and local embeddings with Azure OpenAI text-embedding-3-large. Adds semantic ranking, enterprise scale, managed indexing pipelines, and monitoring. Migration from Option B is a configuration-level change, not a rewrite.

✅
Bottom line: Option B is worth the 4-hour investment if you need to demonstrate the product to stakeholders or get Azure resource approval. The ability to point to a question and say "this answer comes from this exact Microsoft Learn page, here is the URL" is a significantly stronger proof-of-concept than "Claude remembered this." Option A is sufficient for ongoing development work.
