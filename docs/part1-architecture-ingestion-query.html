Architecture, Ingestion & Query Flow

System architecture, how documents become vectors, and how a user question travels end-to-end through the RAG pipeline.

Section 1 — High-Level Architecture

The CertMasterAI system is a RAG-grounded exam question generator. No question is allowed to come from LLM training memory alone — every answer must be traceable to retrieved Microsoft Learn documents. This architecture enforces that contract at every layer.

Key insight: The LLM is given only the retrieved context and is instructed to compute its own grounding score. If its answer relies on training memory rather than the provided context, it must self-report a low score — which the grounding gate then catches and drops. This is your anti-hallucination contract.

Section 2 — Document Ingestion Flow

Ingestion is a one-time (or periodic) operation that converts raw text documents into a searchable vector index. It must complete before any user query can succeed. Think of it as building a library catalogue before opening to the public.

Embedding Generation Code

generator.py : get_embedding() — lines 165–175
async def get_embedding(self, text: str) -> Optional[list[float]]:
    try:
        client = self._get_openai_client()
        resp = await client.embeddings.create(
            model=settings.AZURE_OPENAI_EMBEDDING_DEPLOYMENT,  # text-embedding-3-large
            input=text,
        )
        return resp.data[0].embedding   # list of 3072 floats
    except Exception as e:
        logger.warning("Embedding generation failed: %s", e)
        return None

What if Azure AI Search is down? The retriever detects an empty result set or exception and automatically falls to ChromaDB. If ChromaDB also has no data, a fallback doc_id "fallback-001" is returned, which triggers the FALLBACK_SYSTEM_PROMPT path — the LLM generates from its own expert knowledge, with grounding check bypassed. The question is still valid but not RAG-grounded.
