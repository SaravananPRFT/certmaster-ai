Section 6 — Azure AI Search Architecture

Azure AI Search is a fully managed cloud search service. For CertMasterAI, it's the Tier 1 production retriever — it provides hybrid search (keyword + vector), semantic reranking, and enterprise security that ChromaDB cannot match.

What Azure AI Search Does That ChromaDB Cannot

Both Supported

Vector Search (HNSW)

Approximate nearest-neighbor search over high-dimensional embeddings. Same algorithm, different runtime — ChromaDB is in-process, Azure is cloud-managed.

Azure Only

BM25 Keyword Search

Inverted index, TF-IDF scoring. Finds documents that contain the exact words in the query — essential when precise technical terms like "NSG" or "RBAC" must be matched literally.

Azure Only

Hybrid Search (RRF Fusion)

Merges BM25 and vector result lists using Reciprocal Rank Fusion. Gets keyword precision AND semantic recall in a single query. Best results for technical content.

Azure Only

Semantic Reranking

An L2 cross-encoder re-reads the query + top-50 passages and re-scores them with deep semantic understanding. Dramatically improves precision for complex scenario questions.

Both Supported

Metadata Filtering

ChromaDB: where={"exam_code":"AI-102"}
Azure: $filter=exam_code eq 'AI-102' (OData syntax, composable with vector queries)

Azure Only

Enterprise Security

Entra ID (MSAL), RBAC, Private Endpoints, Customer-Managed Keys (CMK), network isolation. ChromaDB has no authentication model.

Section 7 — ChromaDB vs Azure AI Search

This is the question every architect must answer at design time: when do you use which? The answer is almost never either/or — your project uses both, tiered.

DimensionChromaDBAzure AI Search
Deployment Model Embedded Python library, file on disk. Zero infrastructure. Managed cloud service. Azure-hosted, auto-scaled.
Cost (small scale) Free (open source) ~$73/month (Basic tier)
Cost (large scale) Infrastructure + ops cost if self-hosted at scale Scales with storage and RU usage; predictable pricing
Local Development Perfect — pip install chromadb, works offline Requires Azure account; no local emulator
Search Types Vector only (cosine/L2/dot) Vector + BM25 + Hybrid (RRF) + Semantic reranking
Scalability Single-node; ~1M vectors practical ceiling Multi-shard, multi-replica; billions of vectors; 99.9% SLA
Metadata Filtering Yes — where={"exam_code":"AI-102"} Yes — OData $filter, composable with vector queries
Security None (filesystem access control only) Entra ID, RBAC, Private Endpoints, CMK encryption
Semantic Ranking Not supported L2 cross-encoder reranker (4 semantic queries/second on Basic)
Hybrid Search Not supported BM25 + Vector fused via Reciprocal Rank Fusion
Incremental Ingest Manual upsert (your code does this: collection.upsert()) Indexer with change detection; watermark-based incremental
When to Use Dev, prototyping, CI tests, offline / air-gapped Production, enterprise, compliance requirements
Role in CertMasterAI Tier 2 fallback — chroma_retriever.py Tier 1 primary — azure_retriever.py

Concrete Example: When Hybrid Search Wins

Query: "AZ-104 virtual network NSG deny rule"

BM25 (keyword) alone: Finds: documents containing "NSG", "deny", "rule" Misses: docs that say "network security group inbound block" because the words don't match exactly Vector (semantic) alone: Finds: semantically similar content about network security Overincludes: general networking docs ranked too high Misses: docs where the specific term "NSG" is critical Hybrid + Semantic Reranking: BM25 finds: [NSG-doc1, NSG-doc2, firewall-doc, ...] Vector finds:[NSG-doc1, network-doc5, security-doc3, ...] RRF fusion: NSG-doc1 appears in both → highest combined score Reranker: Cross-encoder reads each passage against query → Re-ranks, surfaces the most precisely relevant Result: 40% better precision for technical Microsoft exam content compared to vector-only search Why does this matter for CertMasterAI? Exam questions hinge on precise technical terms: "RBAC" vs "Azure Policy" "NSG" vs "Azure Firewall" "SAS token" vs "managed identity" BM25 ensures these precise terms are never missed. Semantic ranking ensures the overall passage is relevant.
The Right Mental Model: BM25 = "does the document contain these exact words?" (precision). Vector = "does the document mean the same thing?" (recall). Hybrid = both. Semantic reranking = "of the hybrid results, which is truly most useful?" The four-stage pipeline (BM25 + vector → RRF → reranker) is the state of the art in RAG retrieval as of 2026.

ChromaDB vs Azure AI Search in Your Retriever

retriever.py — tiered strategy
async def retrieve(self, query, exam_code, objective, top_k, embedding):

    # Tier 1: Try Azure AI Search first (production quality)
    if settings.AZURE_SEARCH_ENDPOINT:
        try:
            chunks = await self.azure_retriever.retrieve(
                query=query, exam_code=exam_code, top_k=top_k,
                embedding=embedding
            )
            if chunks:
                return chunks   # ← use Azure results
        except Exception as e:
            logger.warning("Azure Search failed: %s", e)

    # Tier 2: ChromaDB fallback (local, no cloud needed)
    chunks = chroma_retriever.retrieve(
        query=query, exam_code=exam_code, top_k=top_k
    )
    if chunks:
        return chunks     # ← use Chroma results

    # Tier 3: Fallback document (triggers knowledge-based generation)
    return [self._fallback_doc(exam_code, objective)]
